Numbers get lost in translation

Filing tables split a dollar sign into its own cell, separate from the value. A naive parser keeps the symbol and silently drops the figure.

Data Center revenue was $75.2 billion, up 92%, driven by $9 billion in new deals.

Flagged: $9 billion appears in none of the retrieved excerpts.

Confidence isn’t the same as correctness

A language model answers smoothly whether or not the source says so. Fluency tells you nothing about whether a number is real, so code checks every figure.

The right quarter is buried in ten similar ones

Every filing repeats the same disclosure, worded almost identically, with different numbers. Search has to know the difference — semantics alone can’t.

What EdgarIQ actually does

Six stages, each accountable for a specific part of getting the answer right.

  1. 1

    Ingest

    Pull 10-K and 10-Q filings directly from SEC EDGAR’s public API.

  2. 2

    Parse

    Strip layout noise; keep only tables that carry financial data.

  3. 3

    Retrieve

    Semantic and metadata search together — a named date beats a guess.

  4. 4

    Draft

    Answer using only the retrieved excerpts, citing the filing for every figure.

  5. 5

    Verify

    A numeric check confirms each figure actually appears in the source.

  6. 6

    Critique

    A second pass flags any claim the evidence doesn’t clearly support.

Violet stages check the answer before it reaches you.
